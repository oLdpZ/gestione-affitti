# 5. Parallelization waves

Il workflow è 1-human + 1-Claude, quindi sequenziale. Però alcune sotto-task **possono essere accorpate in un singolo commit per atomicità** invece di splittare:

- **Wave 1 (foundation)**: T00 → T01 → T02 → T03 → T04 [gate]. Sequenziale obbligato.
- **Wave 2 (data model)**: T05 → T06 → T07, T08 (bugfix indipendenti dopo data model, possono swap).
- **Wave 3 (UI + state)**: T09 → T10 → T11 → T12 → T13 → T14 (cestino + undo). T15 → T16 (snapshot, indipendenti da cestino, può swap con cestino se vuoi).
- **Wave 4 (validation + salute dati)**: T17, T18 in parallelo concettuale (entrambi richiedono pushErrore — se T18 fatto prima, T17 può chiamare pushErrore reale). T19 → T20 (salute dati). T21 → T22 → T25 (validation + fixture update, **squashabili in un commit**).
- **Wave 5 (auto-purge + toast UI)**: T23 → T24. Indipendenti tra loro.
- **Wave 6 (test)**: T26, T27, T27b, T28 — completamente indipendenti, possono essere scritti in qualsiasi ordine.
- **Wave 7 (gate)**: T29.

**Atomicità raccomandata**: ogni T = un commit, eccezione T22+T25 squashabili.
