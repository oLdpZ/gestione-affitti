# Plan 05-01: Schema DDL + RLS + `get_user_data()` RPC + dual-write reads

**Requirements:** REQ-SCHEMA-01

## Goal
Creare il nuovo schema Supabase per-entità (6 tabelle con RLS+updated_at trigger+indexes), pubblicare l'RPC `get_user_data()` per un single-roundtrip-at-login, e cablare `caricaDatiUtente()` in dual-read (preferenza nuovo schema, fallback blob legacy). Aggiungere `idb-keyval` CDN al precache SW. Wave 1 foundation: tutto il resto della Phase 5 dipende da questo.

## Context summary
- DDL **idempotente** (`if not exists`) — verbatim da RESEARCH §2 (CONTEXT linee 26-32 LOCKED schema target).
- RPC con `security invoker` + `set search_path = public` + `stable` — RESEARCH §3 (RLS gates ogni sub-select; INVOKER batte DEFINER per minor surface area).
- `coalesce(json_agg, '[]'::json)` su ogni sub-select per evitare null su array vuoti (R-NEW-3).
- Rollback flag `localStorage.usaNuovoSchema` default `true`; flip a `false` forza percorso blob (CONTEXT linea 43).
- Dual-write Phase 1 di DEC-012: `caricaDatiUtente()` legge entrambi — se RPC ritorna data con `proprieta.length > 0` usa nuovo schema; altrimenti fallback blob (RESEARCH §7 mechanics).
- `idb-keyval@6.2.2` CDN UMD pinned (RESEARCH §4): `https://cdn.jsdelivr.net/npm/idb-keyval@6.2.2/dist/umd.js`.
- SW `CACHE_NAME` bump da `gestione-affitti-v1` → `gestione-affitti-v2` (precache list cambia → forza activate cleanup).

## Threat model
- **Auth bypass via RLS holes**: ogni policy è `for all using (user_id = auth.uid()) with check (user_id = auth.uid())` — copre SELECT/INSERT/UPDATE/DELETE. Verifica T-05-01-04 step 5: anonymous select ritorna 0 rows.
- **SECURITY DEFINER privilege escalation**: NON USATO — la RPC è `security invoker` (RESEARCH §3 falsification). Quindi auth.uid() risolve all'utente chiamante e RLS si applica naturalmente. Nessun search_path attack possibile.
- **Migration ordering data race (multi-tab)**: se 2 tab dello stesso utente caricano simultaneamente, entrambi fanno `get_user_data()`; entrambi leggono lo stesso JSON; le state `lastPullAt` differiscono ma sono entrambi corretti. Nessuna write in questo plan, quindi no race. La race su mutation queue è gestita in plan 05-02.
- **Idempotenza migration file**: tutti i `create table if not exists` + `create or replace function`. Riapplicare il file è no-op. `create policy` può fallire su rerun (no IF NOT EXISTS in pg per policies) — mitigation documentata in T-05-01-01 action ("prepend drop policy if exists").

## Risks & mitigations
- **R-NEW-3 (json_agg ritorna null su zero rows)**: coperto da `coalesce(..., '[]'::json)` in ogni sub-select.
- **R-NEW-5 (RPC timeout)**: PR2b family-tier ~600 rows ≪ 8s default timeout. Postgres `EXPLAIN ANALYZE` da rifare se utenti raggiungono >10k rows totali.
- **OQ-1 risolta**: shape conversion lato client (`adattaShape`) — meno rischio rotture su nuove colonne lato server.
- **OQ-3 risolta**: blob localStorage (PR1) preservato come ultimate fallback — `salva()` continua a scrivere blob in Phase 1 (plan 05-02 dual-write).
